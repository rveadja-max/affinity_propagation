ATTACK 1 [MAJOR] The k used in the Q3 comparison is never fixed, and the plan's own example picks k from the labels
Where: §4 table "Comparateurs à **k imposé par AP**" with `apcluster(negDistMat(r = 2), X, q = …, …)`; §5.2 "5.3 Q3, comparaison à k égal"; §3.2 and §3.6, where the only comparison actually run is "à k = 3 : AP (`q = 0`) 147,62 ; `pam(as.dist(D²), 3 …)` 146,68"
Problem: Nothing says which `q`, and so which k, feeds the Q3 table, for Iris or for Wine. On Iris the plan's own grid gives k = 9 (median default), 3, 5, 6 … 149, and ADR 0003 (B.2) says "pour chaque k produit par AP". The plan never picks one k, a few, or all of them. The only worked example uses k = 3 through `q = 0`, and 3 is the number of species. If the user copies that example, the labels have chosen the comparison point. That is the leak that E9 / CLAUDE.md forbid ("Aucune fuite : les étiquettes ne servent jamais à construire les clusters"). §5.1 even says the 3-cluster range of `q` must be "présentée comme une observation, pas comme un réglage". As written, §5.3 and script `03_comparaison_k_egal.R` cannot be built without guessing, and the obvious guess breaks a stated rule. The plan should name a label-free rule for k (the default median, a fixed set of `q`, or every k in the grid) and say how it applies to Wine.

ATTACK 4 [MAJOR] The "Fini quand" check for §3 cannot work: `formals()` does not return the defaults of `apcluster`
Where: §5.2 §3 "*Fini quand :* le tableau des défauts est généré par un script (`formals()` ou la sortie de l'aide)"; §5.3 `analyses/04_defauts_apcluster.R` → "`defauts.csv` (depuis `formals()`)"
Problem: `apcluster` is an S4 generic. Checked with apcluster 1.4.14: `names(formals(apcluster))` returns `"s" "x" "..."`. `names(formals(getMethod("apcluster", c("matrix","missing"))))` also returns `"s" "x" "..."`, because the defaults sit in an internal `.local` function. The planned script would therefore write a `defauts.csv` with no `q`, `lam`, `maxits`, `convits`, `nonoise` or `seed`. The §3 check could not be met, and the user would be tempted to copy the defaults by hand, which the plan itself forbids. The plan has to name a method that works (for example parsing the method body or `.local`), or stop requiring that this table be generated by a script.
