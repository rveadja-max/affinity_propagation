ATTACK 2 [MAJOR] The "no hand-typed number" check misses integers
Where: §4.3 §6 "Fini quand" and §4.5: `grep -nE '[0-9]+[.,][0-9]+' Report/Affinity_propagation_rapport.qmd`
Problem: The regex only matches decimals. The plan's own key results are integers: "q = 0 → 3 clusters", "9 clusters", "149 à q = 1", "109 / 113 / 210 itérations", "100 sous-échantillons". Counterexample: someone types "à λ = 0,9 l'algorithme converge en 210 itérations" by hand. `210` passes the grep, and `0,9` passes as a protocol parameter. So the CLAUDE.md rule "chaque chiffre du texte doit correspondre à une sortie réellement produite par un script" is not enforced for the very numbers the plan puts at the centre (k as a function of q, iteration counts).

ATTACK 4 [MAJOR] The control column cannot fail
Where: §4.4 table header "Contrôle à la première exécution (valeurs du 01/11, seed 1234)" + "`GRAINE <- 20261101L` ... Une valeur différente de la colonne « Contrôle » n'est pas une erreur en soi (la graine change)"
Problem: The scripts are told to use seed 20261101, but the reference values come from seed 1234. The plan then says a mismatch is not an error. As written, every outcome passes, so the acceptance check checks nothing. Example: `02` returns AP cost 152 because a scaling bug used raw instead of z-scored data. Under the stated rule this counts as "graine change, à expliquer", not a failure. The fix is one line: run the controls with `seed = 1234` (or give the values for 20261101). It is missing.
