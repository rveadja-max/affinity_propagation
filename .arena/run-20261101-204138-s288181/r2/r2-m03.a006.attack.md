ATTACK 1 [MAJOR] Chantier 0 cannot pass its own day-1 check: `metadata-files: [results.yml]` points to a file that does not exist yet
Where: §4.1 YAML block (`metadata-files: [results.yml]      # nombres produits par les scripts`) + "Vérification : `quarto render …` affiche « Output created »", scheduled Dim. 01/11 in §4.4; `results.yml` is only produced by `00_utils.R` / scripts 01-02 on Lun. 02/11.
Problem: Quarto aborts when a listed metadata file is missing. Reproduced with Quarto 1.10.18 on a minimal file with `metadata-files: [results.yml]` and no results.yml: "Could not find metadata file 'results.yml'" / "WARN: Error encountered when rendering files". Following the plan in order on 01/11 breaks the build that Chantier 0 is supposed to fix, and the "tested on a copy" claim held only because a results.yml was present in the test copy. The plan should add that line on 02/11, or commit an empty `results.yml` stub in Chantier 0. As written, the user hits an error on the first step.

ATTACK 2 [MAJOR] The reproducibility check in §4.2 always fails, so it tests nothing
Where: §4.2 "Après chaque script : vérifier que deux exécutions de suite donnent des fichiers identiques (`Rscript … && md5sum Report/tables/*`)" against the script 02 row, whose outputs include "ARI, NMI, **temps**. Fichier `tables/t_comp.md`".
Problem: execution times change on every run, so `t_comp.md` never has the same md5 twice, and the check fails for script 02 whatever the code does. The check also leaves out `Report/results.yml`, which `00_utils.R` fills by "ajout de valeurs". If that means appending, a second run writes duplicate YAML keys (or keeps stale ones), and the md5 check never sees it. Timing has to go in a separate untracked file, or be dropped from tables covered by the check, and `results.yml` has to be rewritten whole on each run and included in the check.

ATTACK 3 [MAJOR] The comparison does not say which preference fixes k, and the plan's own numbers show this choice drives the result
Where: §4.2 script 02 "à k fixé par AP : AP, `pam`, `kmeans(nstart = 25)`, Ward" / critères table "`apcluster(negDistMat(r = 2), x, q = …, seed = …)`"; §3.1 Enjeu 1 gives k = 9 at the median, k = 5 for q = 0.05-0.25, k = 3 at q = 0 (I re-ran these and they match); §4.3 partie 4 "pourquoi ce choix (pas k = 3, qui serait une fuite)".
Problem: `q = …` is never set. Depending on q, the comparison runs at k = 9, 5 or 3, and those are three different experiments for §5.2, the TP and the slides. The plan also rules out k = 3 as a leak, but q = 0 (the minimum preference in the sweep) gives exactly k = 3. The user can't tell whether q = 0 is allowed or how to justify a q without looking at `Species`. This is the key setting of the key experiment (Q3), and the user would have to guess it. The plan needs a label-free rule (for example the `apcluster` default median, or a q fixed in advance in `00_config.R` with its justification) written down before script 02 runs.

ATTACK 4 [MAJOR] Coupling the promo TP to the report pipeline breaks on student machines
Where: §4.2 "tous les scripts, **y compris** le script pédagogique `tp/Application_Iris.R`, commencent par `source("tp/00_config.R")` et `source("tp/00_utils.R")`" and "les scripts écrivent leurs sorties dans `Report/tables/`, `Report/figures/` et `Report/results.yml`".
Problem: the cadrage (`Affinity Propagation.md`, §4.2) requires a "cas d'usage guidé que l'ensemble des étudiants de la promotion peut exécuter en temps réel sur leurs machines". A student who opens `tp/Application_Iris.R` in RStudio and clicks Source has their working directory set to the home folder or to `tp/`, not the repo root, so `source("tp/00_config.R")` stops with "cannot open file". If it does run, `00_utils.R` writes into the student's `Report/` (and needs `yaml`, which the plan never lists among the dependencies to install). The plan makes the 05/11 TP depend on report plumbing and gives no check for it. The "machine propre" test on 04/11 only runs `capture-environment` and does not say from which working directory. The fix: a self-contained TP script that only reads `00_config.R` through a path that does not depend on the working directory, with no writes to `Report/`.
