ATTACK 1 [MAJOR] The stability protocol (5.5) compares AP to K-means and pam on unequal terms, so the comparison is biased by design
Where: § 5, table row "5.5 Stabilité (Q5) — version minimale obligatoire": « AP à la préférence médiane du sous-échantillon […] même calcul pour K-means (`nstart = 25`) et `pam` au k du jeu complet », together with the note under the table: « k varie entre 7 et 9 d'un sous-échantillon à l'autre ».
Problem: In each subsample, AP's k changes (7 to 9) because the median preference is recalculated, while K-means and pam stay at the k of the full dataset. Each subsample is then scored by ARI against the full-data partition at k = 9. When AP gives 7 clusters, its ARI drops for that reason alone, even if the partition is just as stable, while its competitors never pay that cost. The project rule this plan says it enforces is « Comparaison équitable : mêmes données, mêmes prétraitements, graines fixées, réglages explicités ». The plan does say the variation "mêle deux sources", but only for AP. It still produces a K-means/pam vs AP stability table in which one method changes k and the others do not. A fair version would either fix AP's preference at the full-data value s(k,k), so that only the data vary, or report AP's stability separately from the cross-method comparison. The plan picks neither, and it calls this sub-part "obligatoire" and says it "ne se coupe pas".
