## 2. Choix de la chaîne de production : matrice d'options

**Question :** comment les chiffres et figures des scripts arrivent-ils dans le `.qmd` ?

Échelle : 1 = mauvais, 3 = bon.

| Critère (poids) | A. Chunks R dans le `.qmd` | **B. Scripts → fichiers inclus** | C. Recopie à la main |
|---|---|---|---|
| Traçabilité « chiffre = sortie de script » (×3) | 3 | 3 | 1 |
| Fonctionne aujourd'hui sans rien installer (×2) | 1 (`knitr` absent) | 3 | 3 |
| Rendu rapide et robuste avec le gabarit URCA (×2) | 1 (R relancé à chaque rendu) | 3 | 3 |
| Mêmes scripts réutilisables pour le TP et les slides (×2) | 1 | 3 | 2 |
| Effort de mise en place (×1) | 2 | 2 | 3 |
| **Total pondéré** | **17** | **29** | **22** |

**Choix : B.** Les scripts R écrivent trois sortes de fichiers dans `Report/` :
- des tableaux Markdown **avec légende** dans `tables/` ;
- des figures PDF dans `figures/` ;
- un fichier `results.yml` qui contient les nombres cités dans le texte.

Le `.qmd` les reprend ainsi :
- `{{< include tables/t_q.md >}}` pour un tableau ;
- `![...](figures/k_vs_q.pdf){#fig-kq}` pour une figure ;
- `{{< meta res.k_median >}}` pour un nombre, avec `metadata-files: [results.yml]` dans le YAML.

**Testé sur une copie du `.qmd`** (Quarto 1.10.18, XeLaTeX, gabarit URCA) : l'include, la figure PDF, les renvois `@fig-`/`@tbl-` et `{{< meta >}}` passent tous à la compilation. `{{< var >}}` avec `_variables.yml` ne marche pas pour un rendu de fichier seul : il affiche `?var:`.

Il reste une limite : les tableaux Markdown sont écrits avec `paste()` en base R, ce qui fait quelques lignes de code de plus. L'option A reste possible plus tard, après `install.packages(c("knitr", "rmarkdown"))`. Elle n'est pas nécessaire.

## 3. État des lieux du projet

### 3.1 Contexte et enjeux techniques

- **Sujet :** AP choisit des **exemplaires parmi les observations** par **propagation de messages** : responsabilités r(i,k) et disponibilités a(i,k).
  - Le nombre de clusters est piloté par la **préférence** s(k,k) et par la similarité.
  - Ce sont les **messages** qui sont amortis, avec le coefficient λ.
  - Sources : `analyse_litterature/questions_recherche.md:21`, d'après Frey & Dueck 2007, p. 2-3 du PDF fourni (source A).
- **Enjeu 1 : la préférence.** Mesure locale (R 4.6.1, apcluster 1.4.14, `scale(iris[,1:4])`, `negDistMat(r = 2)`, `seed = 1`) :
  - préférence par défaut (médiane) : **9 clusters**, exemplaires 4, 6, 18, 81, 92, 118, 123, 124, 140, en 210 itérations ;
  - q = 0,05 à 0,25 : 5 clusters ;
  - q = 0 : 3 clusters.

  À q = 0, le croisement avec `Species` (étiquettes utilisées **seulement pour évaluer**) donne :
  - cluster 1 : 50 setosa ;
  - cluster 2 : 41 versicolor et 15 virginica ;
  - cluster 3 : 9 versicolor et 35 virginica.

  *Ce sont des sorties de contrôle, pas encore produites par un script du dépôt. Elles ne doivent pas être recopiées dans le rapport avant d'avoir été régénérées par `Report/scripts/`.*
- **Enjeu 2 : `apcluster` ≠ article d'origine.** Signature vérifiée dans R : `maxits = 1000, convits = 100, lam = 0.9, nonoise = FALSE, seed = NA`.
  - L'amortissement par défaut vaut donc 0,9, contre 0,5 chez Frey & Dueck.
  - Le paquet ajoute un petit bruit aux similarités : il faut fixer `seed` pour la reproductibilité.
  - Il faut le dire dans la partie Implémentation. Il faut aussi corriger « AP est déterministe » dans `methodologie.md:18` : l'algorithme l'est, `apcluster` sans `seed` ne l'est pas.
- **Enjeu 3 : la comparaison équitable.** À k égal (k fixé par AP), sur les mêmes données et avec la même dissimilarité : `pam`, `kmeans(nstart = 25)` et Ward (`methodologie.md:66-73`). Le critère p-médiane rend le résultat défavorable à AP possible (Brusco & Köhn, source A). Ce résultat devra être rapporté s'il apparaît.
- **Enjeu 4 : les métriques.** `mclust` et `aricode` ne sont pas installés (vérifié avec `requireNamespace`). Pour l'ARI et la NMI, deux options :
  - les installer et les citer ;
  - ou les coder en base R (fonction documentée, testée sur un cas connu).

  `cluster` (2.1.8.2) est installé.
