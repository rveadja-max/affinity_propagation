ATTACK 1 [MAJOR] The "résultat négatif pour AP" against `pam` depends on a setting the document never states, and with the default `pam` the result reverses
Where: § 1.6 « Somme des distances euclidiennes au carré aux exemplaires : AP 147,62 ; `pam(k = 3)` 146,68 (médoïdes 8, 140, 95) » ; T4 « Le sondage local donne `pam` légèrement meilleur qu'AP » ; § 1.6 « Q3 donne un résultat négatif pour AP » ; § 2.2 point 4.3, which lists only « comparateurs `pam` ».
Problem: Medoids 8/140/95 and 146,68 only come out when `pam` runs on SQUARED distances (`pam(as.dist(as.matrix(dist(x))^2), 3, diss = TRUE)` → 8 140 95, 146.6847). The call the document actually writes, `pam(x, k = 3)` with default Euclidean distance, gives medoids 8 113 56 and a squared-distance sum of 148.5467. That is WORSE than AP (147.6196, which I reproduced with seed 1234, medoids 8 56 140). So whether the result is negative depends on a dissimilarity choice the plan never mentions, and protocol 4.3 does not fix it either. That breaks the CLAUDE.md rule « comparaison équitable … réglages explicités ». The finding is pushed into the plan (T4, § 1.6, the example in 5.4) as if it were settled. Following the plan as written, the user would write a « résultat négatif » that his own script contradicts.

ATTACK 2 [MAJOR] The table pipeline chosen in D3 cannot work: scripts write CSV, but with no knitr the `.qmd` has no way to turn a CSV into a table
Where: D3 recommendation (b) « les scripts écrivent `Report/figures/*.pdf` et `Report/tables/*.md`, que le `.qmd` inclut » versus § 2.3, where every script outputs `.csv` (`q_sweep_iris.csv`, `lambda_iris.csv`, `comparaison_iris.csv`, `stabilite.csv`) ; T7 « knitr, rmarkdown … ne sont pas installés ».
Problem: D3(b) assumes markdown tables, but no script in § 2.3 writes any `.md`. Without knitr, Quarto has no chunk that can read a CSV. So nothing in the plan says how the numbers in chapters 4-5 reach the PDF, and the user would have to guess (add `knitr::kable` to every script? install knitr after all?). The chapter-5 « Terminé quand » and the § 2.8 checklist both depend on this pipeline.

ATTACK 3 [MAJOR] The reproducibility check in the "done" checklist cannot pass, because one of the CSVs it hashes contains run times
