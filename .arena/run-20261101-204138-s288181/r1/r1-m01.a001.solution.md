## 2. Plan de travail du rapport `Report/Affinity_propagation_rapport.qmd`

### 2.1 Principe d'architecture : une seule source par contenu

```text
analyses/                      (nouveau dossier, nom à valider à deux)
  00_config.R                  graines, paramètres, chemins, versions → un seul endroit
  01_sensibilite_preference.R  Q1+Q2 : balayage de q (Iris, puis Wine)
  02_comparaison_k_impose.R    Q3 : AP vs pam vs kmeans(nstart=25) vs Ward, pour chaque k
                               atteint par AP dans le balayage de 01_ (voir Ch. 6.2)
  03_amortissement.R           Q4 : λ ∈ {0,5 ; 0,7 ; 0,9}, préférence fixée
  04_stabilite.R               Q5 (optionnel) : 100 sous-échantillons à 80 %
  resultats/*.csv, figures/*.pdf, sessionInfo.txt
Report/Affinity_propagation_rapport.qmd   lit resultats/*.csv dans des chunks
                                          `#| echo: false` ; chiffres en `r ...` inline
tp/                            script autonome (un seul fichier pour la promo),
                               mêmes paramètres que 00_config.R
```

Pourquoi cette organisation :
- un chiffre du texte ne peut plus diverger de sa source (règle « chaque chiffre vient d'un script ») ;
- la fiche et les slides lisent les mêmes CSV ;
- le TP reste autonome, pour que la promo n'ait qu'un fichier à ouvrir.

**Garde-fou :** un contrôle vérifie que le TP et `01_` donnent le même k pour le même `q`.
