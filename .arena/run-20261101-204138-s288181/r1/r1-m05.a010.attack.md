ATTACK 1 [MAJOR] The k used for the "equal k" comparison is never fixed, and the plan's own Iris test chose k = 3, which is label leakage
Where: §1.1 "Essai de faisabilité sur Iris, k = 3 : coût p-médiane … 147,62 pour AP contre 146,68 pour `cluster::pam`" ; §2.2 part 4 "comparateurs `pam`, `kmeans(nstart = 25)`, Ward, tous à **k imposé par AP**" and "aucun réglage ne vise k = 3 (fuite)" ; §2.3 step 4 "pour le k d'AP".
Problem: AP's k depends on q. The plan's own output gives q = 0 → 3, q = 0.1 → 5, q = 0.5 (default) → 9, q = 1 → 149 (I reproduced these four values and the 147.62 / 146.68 costs). The plan sweeps 21 values of q but never says which q, and so which k, feeds Q3. The only worked example uses q = 0, the one setting where k equals the number of Iris species. That breaks the plan's own rule in part 4 ("aucun réglage ne vise k = 3"). Its headline "résultat défavorable à AP" is therefore built on a setting the plan forbids elsewhere. Whoever writes `experiences.R` step 4 has to guess the k: default q (k = 9), every q in the grid, or q = 0. Each choice gives a different table, and one of them leaks the labels.
