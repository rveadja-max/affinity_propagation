ATTACK 1 [MAJOR] The 04/11 cherry-pick sets up a broken merge on 10/11, and the plan gives no procedure for 10/11
Where: §6.2 ("On passe par une branche de livraison créée depuis `main`, et on y recopie les commits avec `git cherry-pick`"), §6 ("`main` ne reçoit … le 10/11 (rapport)"), §5 row "Mar 10/11 | — | — | Rapport PDF sur Moodle + `main`".
Problem: Cherry-picking creates copies of the commits on `main`. `Rapport` never contains `livrables/oral`, so on 10/11 the merge base of `main` and `Rapport` is still `e9ab1b1`. Every file that exists on both sides but was edited after 04/11 has no common ancestor version, so git reports an add/add conflict. The plan's own calendar edits those files after 04/11: Sat 07/11 "`01`/`02`/`03` sur Wine" (`analyses/01_sensibilite_q.R` and the others), Wed 04/11 "corrige le TP si le test de mardi a échoué" (`tp/Application_Iris.R`, merged into `Rapport` through §6.1 step 4), and the regenerated `resultats/*.csv`. The plan writes a 15-line procedure for 04/11, but for the final delivery it gives only "+ `main`": no command, no conflict handling, no `Report/`-only path, and nobody assigned (both columns are "—"). That leaves the user to work this out on deadline day. The task asks for "l'ordre et le calendrier jusqu'au 10/11", and the 10/11 step is the one the user cannot carry out from this plan.

ATTACK 2 [MAJOR] The fallback breaks the git rule that decision D7 rests on
Where: §6.2 "Repli si la procédure bloque après 20h : fusionner `Rapport` dans `main` avec le message « rapport en cours, version finale le 10/11 »", against §3 D7 "(a) contredit la règle « `main` = livrables finaux uniquement »".
Problem: The task states the rule: "`main` ne reçoit que les livrables finaux validés à deux". The plan itself says that putting the partial report on `main` breaks this rule (D7), then gives exactly that as the fallback. That fallback also carries the whole of `Rapport` onto `main`: the unfinished `.qmd`, `analyse_litterature/`, and every half-done script. The plan names the deadline problem but gives no fallback that keeps the rule, for example dropping the commits that fail to cherry-pick and delivering the rest, or pushing `livrables/oral` and asking the teacher. Leaving the branches pushed would also work, and §3 D7 itself argues that the teachers can see them.

ATTACK 3 [MAJOR] The "Fini quand" number check cannot pass for the mathematics section
Where: §4.5 awk command ("affiche toute ligne de texte qui contient encore un chiffre quelconque" … "Toute ligne signalée est soit justifiée (année, numéro de section, paramètre listé dans `parametres.csv`), soit corrigée"), used as the finish criterion in §6 and in the 08/11 calendar row.
Problem: The awk removes YAML, code blocks, `` `r …` `` and `[@…]`, but not LaTeX math (`$…$`, `$$…$$`) and not narrative citations (`@clé` without brackets). §3, as the same plan specifies it, contains s(i,k) = −‖xᵢ − xₖ‖², `negDistMat(r = 2)`, O(N²), "page 973", and the cadrage's "10 à 20 pages". I ran the same gsub logic on the line `fig 3 [@b; @c2]` and it still printed. Every equation line with `^2` or an index gets flagged. None of them fits the three allowed reasons, so the rule says to "correct" them. In practice the binôme either cannot reach "Fini quand" or learns to ignore the check, and then real hand-typed results get through. The check needs to strip math and narrative citations, or the allowed list needs to include formulas.
