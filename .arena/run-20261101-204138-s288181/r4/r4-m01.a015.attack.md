ATTACK 1 [MAJOR] The git procedure overwrites a tracked README in the shared branch and falsely says only new files are added
Where: § 6, "Git, dès le 01/11": "Ces fusions n'ajoutent que des fichiers nouveaux (aucun fichier de Marie n'est touché), donc elles ne réécrivent rien de son travail", with the 01/11 row "créer depuis `Rapport`, pousser et fusionner dans `Rapport` ses petites branches (`docs/analyse-litterature`, `docs/bibliographie`, `docs/readme`)".
Problem: `README.md` is not a new file. `git ls-files` lists only `README.md` and the `.qmd`, and the README has been tracked since the initial commit `e9ab1b1` (author `dea0014`). The uncommitted change is a rewrite: `git diff --stat` gives "README.md | 155 ++++----, 79 insertions(+), 76 deletions(-)". Under this plan, `docs/readme` replaces about half of a committed file and is merged into the shared `Rapport` branch "tout de suite, sans attendre". Marie only gets a message afterwards, and the remedy is a `git revert` if she objects. That breaks the task constraints "Le travail de Marie ne doit pas être réécrit sans accord du binôme" and "proposer avant toute réécriture importante". Consent given after the merge is not consent. Assumption, not verified: `dea0014` follows the URCA login pattern (DE Amorim), so the original README is probably Marie's. The plan itself only calls it "le compte propriétaire du dépôt". Fix: either put the README change in a branch that Marie reviews before the merge, or leave it out of the 01/11 batch.

ATTACK 2 [MAJOR] The reproducibility check in the final checklist will always fail, because the plan writes timings into the CSVs
Where: § 8: "`Rscript analyses/run_all.R` régénère tous les CSV et `sessionInfo.txt` ; `git status` ne montre ensuite aucun CSV modifié". Compare § 5.4: `comparaison.csv` holds "ARI, critère p-médiane (AP et `pam` seulement), temps", and § 4.4 / § 4.2 say the CSVs are committed so that "les CSV commités montrent dans `git diff` quand un résultat change".
Problem: wall-clock time differs on every run and on every machine. A clean `run_all.R` therefore always rewrites `comparaison.csv`, `git status` always shows it as modified, and this "terminé" item can never be ticked. The check also cannot tell a real change in results from timing noise, which defeats the stated purpose of committing the CSVs. Counterexample: run `run_all.R` twice in a row on the same machine and the `temps` column differs. Fix: write timings to a separate file that is not committed (e.g. `resultats/temps.csv` in `.gitignore`), or exclude that column from the check.

ATTACK 6 [MINOR] The fix for "déterministe" goes too far: the checklist bans the word, including where it is true
Where: § 8: "`methodologie.md` l. 18 et l. 80 corrigées … (aucune mention d'algorithmes « déterministes »)". § 3.2 point 3 calls "AP est déterministe à données et paramètres fixés" a "prémisse fausse".
Problem: the Frey & Dueck algorithm is deterministic. The randomness comes from `apcluster`'s default tie-breaking noise (`nonoise = FALSE`, `seed = NA`), so it belongs to the implementation. Ward (`hclust`) and `pam` are deterministic too. I checked: `apcluster(s, q = 1, seed = sd)` gives 149 or 150 depending on `sd` (15/5 over 20 seeds), so the l. 18 sentence is indeed wrong about `apcluster` with default settings. But the correct rewrite is "l'algorithme est déterministe ; l'implémentation `apcluster` ajoute un bruit aléatoire sauf `nonoise = TRUE`, d'où `seed` fixée". Banning the word outright pushes the binôme toward a wrong answer if the jury asks at the oral "AP est-il déterministe ?".
