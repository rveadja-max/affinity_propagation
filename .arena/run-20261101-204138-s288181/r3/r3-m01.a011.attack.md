ATTACK 1 [MAJOR] The fallback for the title page on 09/11 makes the final render fail
Where: §5.2 « Page de titre et YAML », step 3: « Porte du lundi 09/11 : si aucune réponse, retirer `diplome`, `coefficient` (…) du YAML. Le libellé reste avec une valeur vide (défauts `\diplome{}` et `\evaluation{}` de la classe, `memoirerecherche.cls:130,133`) ». Repeated in §5.7 (« ou sont absents »), §6 (« champs retirés le 09/11 ») and §7 decision 6.
Problem: the class sets an empty default only for `\diplome` and `\evaluation` (`memoirerecherche.cls:130,133`). It sets none for `\coefficient`, which is only defined at `:109` and is then used unconditionally at `:162` (`\textbf{Comptant pour :} \@coefficient`). `template.tex:106` emits `\coefficient{…}` only when the YAML field exists. So removing `coefficient` leaves `\@coefficient` undefined. I tested this in a copy, using the plan's own YAML from §5.2 with `diplome` and `coefficient` removed: `quarto render` exits with 1 and the log shows `! Undefined control sequence. \maketitle ...{Comptant pour :} \@coefficient`. With both fields present, the same file renders (exit 0). The plan's own citation leaves out `coefficient`, but its step removes it anyway. So the documented fallback breaks the report one day before the 10/11 deadline, and the gate's « Fini quand » (`quarto render … produit la page de titre URCA`) cannot pass. A working fallback is `coefficient: ""` (or keeping the key), not deleting it. The plan should have tested this path the way it tested the main YAML.
