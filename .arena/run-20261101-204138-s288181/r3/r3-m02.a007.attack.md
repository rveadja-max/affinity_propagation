ATTACK 1 [FATAL] The headline stability result ("le classement change de signe avec la graine") comes from an RNG bug in the solution's own control command: 99 of the 100 "sous-échantillons" are the same subsample
Where: §0 point 8 ("AP 0,905 et K-means 0,975 avec la graine 1234, mais AP 0,974 et K-means 0,839 avec 20261101 … on ne peut donc rien conclure"); §2.2 row "Stabilité par sous-échantillonnage"; §4.4 control command, loop `set.seed(G); for (b in 1:100) { i <- sort(sample(150, 120)); aa <- apcluster(negDistMat(x[i, ], r = 2), q = 0, seed = G); … kmeans(x[i, ], 3, nstart = 25) … }`
Problem: `apcluster(…, seed = G)` calls `set.seed(seed)` on the global RNG and does not restore the previous state. The installed source shows `if (!is.na(seed)) set.seed(seed)` followed by `randomMat <- matrix(rnorm(N * N), N)`. Inside the loop, every iteration therefore resets the generator to G. Each iteration then consumes the same rnorm(120×120) and the same kmeans draws, so every `sample()` from b = 2 onward returns the same indices. I checked this by running the solution's loop and counting distinct subsamples over 20 iterations: **2 distinct** with G = 1234 and **2 distinct** with G = 20261101. Its "100 tirages" are one random subsample plus one repeated 99 times. As a result, the means 0,905/0,975 and 0,974/0,839 measure the luck of a single subsample, and "changes sign with the seed" is an artefact. I reran the same protocol with 100 genuinely distinct subsamples drawn up front (`idx <- replicate(100, sort(sample(150,120)), simplify = FALSE)`) and got AP 0,929 / KM 0,938 with seed 1234 and AP 0,917 / KM 0,940 with seed 20261101. There is no sign change, and K-means comes out slightly ahead with both seeds. The false finding is then used to drive the plan. It justifies switching `05` to 10 seeds, the item "on ne lâche jamais `05` avec plusieurs graines", the planned "résultat nul" sentence for Tab. 4, and req. 12 in §7. It also breaks the project rule that a figure must come from an actually correct run.

ATTACK 2 [MAJOR] The plan writes the same bug into every future script, and its own acceptance test requires the script to reproduce the bad numbers
Where: §4.4 preamble ("`seed = GRAINE` passé à chaque `apcluster()`, `set.seed(GRAINE)` avant `kmeans()` et les tirages"); `05` row ("Contrôle de cohérence de la stabilité : … l'ARI moyen doit retomber sur AP 0,905 / KM 0,975 et AP 0,974 / KM 0,839 si l'ordre des tirages est celui de la commande de contrôle"); §5 Sam 07/11 ("contrôles du §4.4").
Problem: following this rule in `05_stabilite_standardisation.R` (seed passed to each `apcluster()` inside the resampling loop) gives 2 distinct subsamples per seed again, for every one of the 10 seeds. So moving to `GRAINE + 0:9` does not fix anything: it gives 10 × 2 subsamples. The "contrôle de cohérence" makes things worse. A correct script (draws generated before the loop, or the RNG state saved and restored around `apcluster`, or `nonoise = TRUE` without a seed inside the loop) will *not* match 0,905/0,975. Under the plan's rule, that correct result looks like an unexplained deviation, while the buggy script "passes". The plan needs an explicit instruction: generate all subsample indices before the loop, or never pass `seed` to `apcluster()` inside a resampling loop. It also needs a check that `length(unique(indices)) == 100`. Neither is given.
